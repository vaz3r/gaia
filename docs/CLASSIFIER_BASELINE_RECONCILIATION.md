## 12. Loss and Scheduler Verification

Line-by-line inspection of `apps/classifier/src/train_transformer.py` revealed:
- **Model Class**: `AutoModelForSequenceClassification.from_pretrained("sentence-transformers/all-MiniLM-L12-v2", num_labels=len(le.classes_))` (`BertForSequenceClassification`).
- **Hidden Size**: 384 dimensions.
- **Classification Head**: `Linear(in_features=384, out_features=8)`.
- **Dropout**: Hidden dropout 0.1, attention dropout 0.1, classifier dropout 0.1.
- **Optimizer & Weight Decay**: `AdamW(model.parameters(), lr=2e-5)`. `weight_decay` is not explicitly passed, defaulting to PyTorch `AdamW` default of `0.01`.
- **Warmup Misconfiguration**: Warmup steps are configured as `len(t_train_dl) // 10` (~24 steps), which is 10% of **one epoch**, resulting in only **~3.3% warmup** over a 3-epoch training run.
- **Gradient Clipping**: **MISSING** (`torch.nn.utils.clip_grad_norm_` is never invoked).
- **Loss Normalization**: Computed as `(per_sample_loss * s_weights).sum() / (s_weights.sum() + 1e-8)`. This correctly computes the batch sample-weighted average.
- **Class and Sample Weight Multiplication**: Class weights $W_{\text{class}}$ enter `CrossEntropyLoss(weight=class_weights, reduction="none")`, and are then scaled per sample by $w_i \in \{0.40, 1.0\}$, properly applying compound weighting.
- **Duplicate Influence**: 278 duplicate rows in `training_combined_v10_true.jsonl` are drawn multiple times per epoch and receive double gradient weight.
